# TrendDrop 화면별 기능 체크리스트

> 현재 코드 기준으로 각 페이지가 UI 섹션별로 어떤 기능을 갖고 있는지, 그리고 각 기능이
> 실제로 얼마나 완성되어 있는지 정리합니다. `/collection-log`, `/collection-log-v-he`는
> 내부 개발용 로그 화면이라 이 체크리스트에서는 제외했습니다.
>
> 🟡 항목은 지금은 mock/localStorage 기반 프로토타입이고, 실제로는
> [trend-data-schema-and-api-spec.md](trend-data-schema-and-api-spec.md) /
> [page-analysis-and-backend-design.md](page-analysis-and-backend-design.md)에 설계된 API·스키마가
> 붙으면 ✅로 전환됩니다. 각 섹션 끝에 **"실데이터 연동 경로"**로 필요한 API/스키마와
> 아직 스키마에 없어서 별도 설계가 필요한 부분을 표시했습니다.

**범례**

- ✅ 완성 — 프론트·백엔드 모두 실제로 동작
- 🟡 프론트만 완성 — UI/인터랙션은 다 되어 있지만 mock 데이터거나 백엔드 미연동
- ❌ 구현예정인 기능

## 1. `/` 홈 — 실시간 랭킹

### 1.1 랭킹 리스트

- 🟡 실시간/24시간 탭 전환
- 🟡 카테고리 필터 탭
- 🟡 LIVE 토글(8초 간격 자동 갱신 on/off)
- 🟡 타임머신 스크러버(과거 12개 시점 이동)
- 🟡 타임랩스 재생/일시정지(자동 진행 후 최신 시점에서 정지)
- 🟡 실시간 하이라이트 티커(신규/급상승 키워드 배너, 클릭 시 해당 행으로 스크롤)
- 🟡 순위 변동 FLIP 애니메이션 + 상승/하락/신규 플래시 하이라이트
- 🟡 미니 스파크라인(막대형 마이크로 차트)
- 🟡 등락 배지(▲상승/▼하락/NEW/-)
- 🟡 요약 통계(추적 키워드 수·신규 진입·최고 상승률) + 롤링 숫자 애니메이션
- 🟡 풀투리프레시(터치 기기, 실시간 모드 한정)
- 🟡 커맨드 팔레트에서 넘어온 카테고리 필터 자동 적용
- 🟡 랭킹 행 클릭 → 키워드별 상세 페이지 이동
- 🟡 관심 키워드 즐겨찾기(★ 토글, `localStorage` 저장) + "관심 키워드" 칩 섹션(급상승 배지 포함)
- 🟡 "내 피드" 탭(온보딩에서 고른 관심 카테고리로 필터링)
- 🟡 랭킹 행 호버 프리뷰(250ms 지연, 성장률·스파크라인·"왜 뜨나" 한 줄 미리보기, 타임랩스 재생 중엔 비활성화)

> **실데이터 연동 경로**: `GET /api/trends?period=realtime|daily`(스펙 3.2절) 하나로 탭 전환·카테고리 필터·요약 통계·FLIP·스파크라인·등락 배지·호버 프리뷰가 한 번에 ✅ 전환됩니다. 타임머신·타임랩스·실시간 티커는 `trend_snapshots`를 시간 버킷으로 묶는 실 이력 계산이 추가로 필요합니다(연동 2단계). 관심 키워드 즐겨찾기·"내 피드"는 `localStorage` 기반이라 지금 그대로도 완결된 기능이며, 기기 간 동기화가 필요해질 때만 `users`/`watchlist_items` 연동이 필요합니다.

### 1.2 수집 컨트롤

- ✅ "최신 트렌드 수집" 버튼(실제 백엔드 파이프라인 호출·DB 저장)
- ✅ 수집 결과/에러 메시지 표시
- ✅ 수집 기록 페이지 링크
- ✅ 수집 완료 후 랭킹 리스트에 결과 자동 반영

### 1.3 워치리스트 패널

- 🟡 키워드/메타 설명/점수 카드 리스트 표시
- 🟡 키워드 저장/삭제

> **실데이터 연동 경로**: `users`/`watchlist_items` 테이블 신설(최소한의 익명 세션 로그인 포함) + `GET`/`POST`/`DELETE /api/watchlist`(스펙 3.6절) 연동 필요. 세 섹션 중 백엔드 설계가 가장 늦게 필요한 영역.

### 1.4 온보딩

- 🟡 첫 방문 시 관심 카테고리 선택 오버레이(최대 3개, `localStorage` 저장, 포커스 트랩·ESC·탭 순환 지원)

> **실데이터 연동 경로**: 로컬 저장 기반이라 백엔드 없이도 완결된 기능. 로그인이 붙어 기기 간 동기화가 필요해지면 `users` 계정에 선호 카테고리를 옮겨 담으면 됨.

## 2. `/explore` 탐색

### 2.1 카테고리 × 시간 히트맵

- 🟡 셀 진하기로 heat(0~100) 표시
- 🟡 열 헤더에 시점 라벨, 최신 열 강조
- 🟡 행(카테고리) 클릭 → 필터 적용 후 홈으로 이동
- 🟡 실제 DB 시계열 기반 heat 계산

> **실데이터 연동 경로**: `GET /api/explore/heatmap`(스펙 3.5절, `trend_snapshots`를 `run_id` × `category_id`로 집계) 연동 시 ✅ 전환.

### 2.2 키워드 A/B 비교

- 🟡 키워드 선택 드롭다운 2개(최신 상위 20개 중 선택)
- 🟡 SVG 순위 궤적 차트(이탈 구간은 선이 끊김)
- 🟡 진입 지점/현재 지점 마커 표시
- 🟡 범례 + 등락 배지
- 🟡 Y축 가이드라인(1위/10위/20위), X축 시간 눈금
- 🟡 실제 DB 시계열 기반 궤적

> **실데이터 연동 경로**: `GET /api/keywords/:slug/history`(스펙 3.4절) 연동 시 ✅ 전환. 드롭다운·차트·마커·범례는 데이터 모양만 맞으면 그대로 동작하도록 이미 구현돼 있음.

## 3. `/trend` 트렌드 상세

- 🟡 상단바(뒤로가기, 순위 배지, 카테고리 태그)
- 🟡 히어로 영역(카테고리, 키워드명, 분석 시점)
- 🟡 핵심 지표 4종(검색 상승률·확산 속도·트렌드 점수·감지 시점)
- 🟡 상승 추이 스파크라인(요일 라벨 포함 SVG 차트)
- 🟡 AI 요약 · 왜 뜨나(요약 + 출처별 근거 리스트)
- 🟡 AI 요약 타이핑 애니메이션("생성 중…" 상태 표시, `prefers-reduced-motion` 대응)
- 🟡 근거 타임라인(언제 어디서 먼저 터졌는지 시간순 이벤트 목록, 채널별 마커)
- 🟡 출처 카드(플랫폼 아이콘, 제목, 참여 지표, 원문 발췌 접기/펼치기, 원문 링크)
- 🟡 연관 키워드 칩
- 🟡 감지 채널 목록(라이브 표시 점)
- 🟡 라우트 파라미터화(`/trend/[slug]`)
- 🟡 실제 키워드별 데이터 조회

> **실데이터 연동 경로**: 상단바·히어로·핵심 지표·스파크라인·연관 키워드 칩·감지 채널·라우트 파라미터화는 `GET /api/keywords/:slug`(스펙 3.3절, `keywords.slug` 라우팅 포함) 연동으로 한 번에 ✅ 전환됩니다. AI 요약·근거 리스트는 `trend_snapshots.summary`/`reasons` 컬럼이 이미 스키마에 있어 **수집기가 실제로 채우고 있는지 확인**만 하면 됩니다. 타이핑 애니메이션은 데이터 연동과 무관한 순수 프론트 로직이라 이미 완성 상태입니다.
>
> ⚠️ **근거 타임라인**은 대응하는 스키마 개념이 아예 없습니다 — `trend_snapshots`는 run당 스냅샷 1행뿐이라 "몇 시 몇 분에 어느 채널에서 처음 포착됐는지" 같은 세분 이벤트 로그를 담을 곳이 없고, 이벤트 테이블을 새로 설계해야 합니다. **출처 카드의 원문 발췌(`excerpt`)**도 `trend_contents`(2.7절: `title`/`metric_label`/`thumbnail_url`만 존재)엔 없는 필드라 별도 컬럼 추가가 필요합니다. 이 둘은 당분간 합성 데이터로 유지하는 게 맞습니다.

## 요약: 우선 처리하면 좋은 항목

1. **랭킹 행 → 상세 페이지 라우팅 버그** (1.1 마지막 항목) — 클릭 경험이 근본적으로 깨져 있어 가장 먼저 고칠 가치가 있음
2. **수집 후 화면 미반영** (1.2 마지막 항목) — 버튼은 동작하는데 결과가 안 보여 사용자가 오작동으로 오인하기 쉬움
3. **`/trend` 라우트 파라미터화** (3장 마지막 두 항목) — 1번 항목의 전제 조건
4. **`/api-lab` 접근 제어** (4장 마지막 항목) — 배포 전 반드시 필요한 보안 항목
